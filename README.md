# 青简 · 小说阅读站（数据源 m.keca.cc）

一个基于 Node + Express + 原生前端的移动端小说阅读网站示例。数据抓取自多个笔趣阁类移动站点（`m.keca.cc` 默认源、`m.mu8net.cc` 等），不落库；后端对列表 / 搜索 / 章节正文 / 封面做带 TTL 的内存缓存，**书籍详情与章节目录采用「目录实时 + 静态元数据指纹缓存 + 末页实时」**：目录、最新章节、总章数、目录末页始终实时回源，静态元数据按目录指纹缓存，一旦出新章立即回源刷新状态 / 更新时间（保证书架「更新」提醒与章节目录 0 延迟）。数据源列表见 `lib/sources/`，可用 `SOURCES` 环境变量调整顺序/启停。

## 功能

- **首页**：强推、分类入口、排行榜入口、各分类最新书籍。
- **分类 / 排行榜**：按分类、按热度（周/月/总点击、推荐、收藏、字数、新书）浏览书籍。
- **书籍详情**：封面、作者、分类、状态、更新时间、简介，以及完整章节目录（支持跳转）。
- **阅读器**：章节正文、上一章/下一章/目录导航，阅读进度自动保存到本地（localStorage）。
- **搜索**：基于本地索引（抓取列表页建立书名/作者索引）的模糊搜索。
- **封面代理**：通过后端代理书籍封面，规避源站防盗链。

## 技术栈

- 后端：Node.js + Express + cheerio（HTML 解析）+ 原生 `fetch`。
- 前端：原生 HTML/CSS/JS，移动端优先，无构建步骤。
- 缓存：服务端内存 TTL 缓存（`lib/cache.js`）+ 浏览器 `Cache-Control` + 前端 localStorage（TTL/LRU）。详见下方「缓存策略」。

## 缓存策略

服务端缓存集中在 `server.js` 的 `TTL` 常量，前端缓存在 `public/assets/app.js` 的 `makeLCache` 实例。

| 数据 | 服务端 | 浏览器 / 前端 |
| --- | --- | --- |
| 数据源清单、分类清单、排行清单 | 24 小时 | 24 小时 |
| 首页、分类、排行、全本列表 | 10 分钟 | 10 分钟 |
| 搜索结果 | 5 分钟 | 5 分钟 |
| 搜索本地索引（keca） | 5 分钟（构建失败 1 分钟内不重试） | — |
| 章节正文 | 24 小时 | 24 小时 |
| 封面图片 | 24 小时 | 24 小时 |
| 书籍静态元数据（书名/作者/封面/分类/简介/状态/更新时间） | 24 小时，**目录指纹校验** | `no-store` |
| 章节目录「非末页」 | 24 小时 | `no-store` |
| **章节目录「末页」 + 目录 + 最新章节 + 章节总数 + 分页信息** | **不缓存（实时）** | **`no-store`** |

**为什么书架 / book 页的更新不受影响**：小说章节是「追加式」的，新章只加在末尾。

- `/api/book/*` 每次**实时回源**取目录、`pager.totalPages`、最新章节与真实总章数 `totalChapters`（分页源也不再用「第 1 页 20 章」冒充总数）。只有静态元数据进缓存，且带**目录指纹**（最新 cid + 章节数 + 总页数）：
  - 目录没变 → 直接复用缓存，零额外请求；
  - **一旦出现新章 → 指纹变化 → 立刻回源刷新 `status`/`update`**，不用等 24 小时 TTL。所以「更新：日期」和状态也是 0 延迟。
  - 空壳元数据（无标题无简介）不缓存；`book.latest` 始终取实时目录末章，不进缓存。
- `/api/chapters/*` 只缓存 `page < totalPages` 的**非末页**（内容永不变）；**末页（最新章节所在页）永不缓存**，每次实时回源。单页书（totalPages=1）也永远实时。
- 这两个接口对浏览器/代理一律 `Cache-Control: no-store`；服务端缓存仅作用于「不会变的部分」。
- 前端 `getBookData()` 直连 `/api/book`，不走任何 localStorage 缓存。

**书架「更新」徽标**：通知型「新章检测」。`localStorage`（`qingjian_seen_latest`）记录上次**点进本书**时看到的最新章节 cid：

- 源站出了新章（实时最新 cid ≠ 基线）→ 亮「更新」；
- 点进书籍页 / 阅读页 → 刷新基线，徽标熄灭，直到源站再出新章才重新亮；
- 书架页本身**绝不主动刷新基线**（否则每次打开都会把基线拉到最新，徽标永远不亮）。
- 冷启动兜底：老用户升级 / 新收藏的书没有基线时，首次在书架看到它就用「当时最新章节」静默建立起点（本次不亮），此后进入正常循环；移出书架会清除基线。

- 缓存只写成功且非空的结果；源站失败 / 返回空目录或空正文时不入缓存，下次仍会重试。前端 `cachedApi` 同样不缓存空结果。
- **防双层叠加**：带缓存的接口用缓存条目的「剩余寿命」做 `Cache-Control: max-age` 并通过 `X-Cache-Remaining` 下发；前端 localStorage 的每条缓存把 TTL 夹到不超过服务端剩余寿命——各层在同一绝对时刻过期，陈旧窗口 = 服务端 TTL，不会变成 2×TTL。
- 强制刷新失败会自动回滚：`?refresh=1` 回源失败时恢复旧缓存，不会因源站抖动丢掉唯一的好缓存；同时带代际保护，旧的慢回源不会覆盖新结果。
- 同一 key 的并发请求合并为一次回源；缓存最多 500 条，超出按最早写入淘汰；重启进程即清空。
- 手动强制刷新：给这两个接口加 `?refresh=1`，会跳过缓存回源并用新结果覆盖缓存。
- 分页源目录页只缓存「非末两页」（`page < totalPages - 1`），即使源站误报总页数也不会把真实末页冻住；`/api/book` 在末页抓到空页时向前回退最多 2 页找真正有内容的末页。
- 判断缓存是否生效：响应头 `X-Cache: HIT / MISS`（章节目录页）、`X-Meta-Cache: HIT / MISS`（书籍元数据，指纹变化时显示 MISS）、`X-Cache-Remaining`（服务端缓存剩余秒数）。

### 前端长列表与并发

- 千章级目录用 `content-visibility: auto`（屏外条目跳过渲染）+ 超过 400 条时分批插入，快速切换排序/翻页有代际保护。
- 书架页每本书并发拉取元数据限流为 4，大书架不会一次性打爆源站。
- 阅读页的 `pager` 快照支持热刷新：打开目录浮层 / 翻到末页边界时重新取一次 `/api/book`，源站在页面打开期间新增的目录页也能翻到；分页加载失败会把页码回滚到上一个有效页。
- 前端默认源不再硬编码，由 `/api/sources` 第一个启用源动态决定（与后端 `SOURCES` 环境变量一致）。

## 运行

```bash
cd novel-site
npm install          # 若遇到 npm 缓存权限错误，可加 --cache 指定可写目录：
                     #   npm install --cache ~/.npm-cache
npm start            # 或 npm run dev（--watch 热重载）
# 打开 http://localhost:3100（端口用 PORT 环境变量可改）
```

> 运行环境需要能访问外网 `m.keca.cc`（代理抓取源站内容）。

## 挂到子路径下（BASE_PATH）

站点可以整站挂在某个子路径（如 `http://host:8080/xiaoshuo/`）下，有两种方式，任选其一即可：

**方式一（推荐）：反向代理剥离前缀**

nginx 用带尾斜杠的 `proxy_pass` 去掉前缀，应用本身不用配置：

```nginx
location = /xiaoshuo { return 301 /xiaoshuo/; }
location ^~ /xiaoshuo/ {
    proxy_pass http://127.0.0.1:3100/;   # 末尾斜杠 = 剥离 /xiaoshuo 前缀
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_connect_timeout 120s;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
}
```

**方式二：应用感知前缀（nginx 不剥离）**

```bash
BASE_PATH=/xiaoshuo npm start
```

此时页面在 `/xiaoshuo/`、接口在 `/xiaoshuo/api/...` 下，nginx 直接 `proxy_pass http://127.0.0.1:3100;`（**不带**尾斜杠）即可。

**实现说明**

- 前端不依赖编译期常量：页面加载时由 `location.pathname` 反推站点前缀（`/xiaoshuo/read.html` → `/xiaoshuo`，根路径为 `''`），所有接口与站内跳转都通过 `BASE` / `U()` 补前缀；`public/*.html` 里的静态资源与页面链接用相对路径，天然跟随前缀。
- 需要在页面里显式覆盖时，可注入 `window.__BASE_PATH__`（例如后端前缀与访问路径不一致的场景）。
- 后端 `BASE_PATH` 只把静态资源与接口挂到该前缀下，缓存策略、指纹校验等行为不变；为空时与原来根路径模式完全一致。
- 不带尾斜杠的前缀入口会 301 到带斜杠版本，保证相对链接解析正确。

> 两种方式不要同时用：要么 nginx 剥离前缀（不设 `BASE_PATH`），要么应用带前缀（nginx 不剥离）。同时用会导致接口路径对不上。

## 数据来源说明

- 章节列表来自源站 JSON 接口 `/api/list`，章节正文来自 `/api/content`（均无需反爬参数）。
- 首页 / 书籍详情 / 分类 / 排行 / 全本 通过抓取 HTML 并解析。
- 源站搜索接口已失效（返回空），故本站搜索改为**本地索引**：启动时预热、索引 5 分钟内复用，覆盖首页、各分类、各排行榜、全本等列表页收录的书籍。搜索范围限于已收录书籍，并非全站。
